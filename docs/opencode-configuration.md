# OpenCode configuration adapter

Selected Skills in new captures have [ACP-server source verification](opencode-skill-sources.md): the actual owned native server must select each captured entry at startup/resume and turn boundaries. Legacy captures retain their separate `debug skill` preflight and its narrower evidence. Neither check proves invocation or complete collision precedence.

The current adapter targets **OpenCode 1.18.16**, with adapter contract `opencode-acp` version `1`. It generates run inputs, verifies native configuration readback, and connects new or restored ACP sessions in the main process. It is exercised against the installed CLI. The durable session coordinator is exercised with this adapter. The desktop factory, Electron IPC, installation version check, and bilingual session controls are connected. Automatic discovery of installed CLIs remains unimplemented.

The provider SDK selection follows the [official custom-provider documentation](https://opencode.ai/docs/providers/#custom-provider). Prompt layering and sampling were checked against the [versioned request preparation code](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/opencode/src/session/llm/request.ts). MCP fields follow the [versioned native schema](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/core/src/v1/config/mcp.ts). Skill names and descriptions follow the [official Skill format](https://opencode.ai/docs/skills/); YAML parsing uses the [document API](https://eemeli.org/yaml/#documents) with bounded frontmatter, duplicate-key checks, no alias expansion, and no custom-tag execution.

## Files, precedence, and state

`OPENCODE_CONFIG` selects the captured `opencode.json`. Generated files include the schema field to avoid a native schema-insertion write. The adapter does not point `OPENCODE_CONFIG_DIR` at immutable inputs: OpenCode's [configuration loader](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/opencode/src/config/config.ts) can write dependency and ignore files into resource directories. Skills use explicit paths instead.

Native configuration remains mergeable. Global configuration, project configuration, automatic resources, and managed settings retain their own precedence; see [OpenCode configuration locations](https://opencode.ai/docs/config/#locations). Project or managed settings can override captured intent. File generation must never be shown as proof that a requested value was applied. The runtime adapter compares the installed version and `debug config` output before ACP startup. Requested values must match; extra native defaults and instruction paths are allowed, with selected instruction order preserved. Agent permission normalization must retain the requested wildcard policy and cannot introduce conflicting per-tool rules. Conflicts stop startup without changing native files.

Readback can contain credentials, so it is compared only in memory, with bounded output and a deadline. Diagnostics expose a static failure code, not native values. Inputs and observed sources are rechecked after readback because native config loading may migrate files. After ACP initialization, both the selected model and agent must match the captured plan. New captures also compare configuration through the [owned ACP server](opencode-instance-configuration.md) at startup/resume and turn boundaries, sharing its authenticated listener with selected Skill-source checks. Legacy captures retain their narrower preflight scope. These observations do not establish complete effective policy, winning-source provenance, model-visible post-hook Prompt content, or behavior between checks.

The source inspector records hashes or absence for known config/rule candidates, traversing the canonical cwd to the nearest Git root. It also captures [native Agent, Mode, and Command directory inventories](native-resource-sources.md), so newly discovered Markdown files invalidate reuse just as changed files do. It records configured global/home locations and supplied managed-file candidates without copying their contents. Coverage stays **partial**: arbitrary plugin/Skill trees, remote sources, included files, legacy formats, and live policy are not fully enumerated. The desktop factory supplies `/Library/Application Support/opencode` on macOS or `/etc/opencode` on Linux. On macOS it also supplies the user and system `ai.opencode.managed.plist` candidates under `/Library/Managed Preferences`, following the [pinned native managed loader](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/opencode/src/config/managed.ts). This enumerates known candidates; it is not complete effective-policy proof.

Native data, cache, state, and temporary files use separate directories under the run's mutable `state` tree. Global config remains at the selected native config home. This is native storage routing, not a filesystem sandbox or a guarantee that third-party plugins write only there. Existing native authentication stores are not imported, so engine-login routes are not yet supported.

## Credentials and interpolation

Snapshots contain secret references and generated environment aliases. `prepareRunLaunch` verifies the snapshot, resolves only its explicit references, deduplicates each reference for that launch, and builds a minimal process environment. Raw values and their injected encodings are kept in memory for diagnostic redaction; they are not written into generated config or the snapshot manifest.

OpenCode substitutes environment macros before parsing JSON. Secret aliases therefore use `json-string` encoding, which escapes quotes, backslashes, and opening braces. Ordinary user strings are also protected from accidental native macro expansion. Only adapter-created file/environment expressions expand. The installed-CLI probe verifies an API key containing both quotes and a file-like macro reaches the local endpoint unchanged. This does not imply that arbitrary user-authored prompt text or native plugin output can be classified as secret automatically.

## Reproducible native probe

```sh
AGENT_MATRIX_TEST_OPENCODE=/absolute/path/to/opencode \
AGENT_MATRIX_OPENCODE_REPORT=/absolute/path/to/report.json \
npm run probe:opencode
```

The opt-in probe uses temporary home/config/state directories, a local HTTP protocol fixture, synthetic credentials, and native pure mode. It exercises `connectOpenCode`, verifies native config readback, provider routing, replacement and appended Prompt content in requests, Markdown and directory Skill discovery, actual directory Skill invocation, streamed response, permission replies, file-read and stdio-MCP tool round trips, MCP cwd/argv/environment, and input integrity after exit. Source/capture deletion demonstrates the session uses its own Skill copies. It cancels both a streaming turn and a turn awaiting permission, then restarts the process and restores the same native session with the previous file/Skill/MCP history. A permission persistence failure closes the runtime. A second conversation runs through the durable coordinator to verify command receipts, explicit permission replies, identical journal/subscription events, known-key redaction in user messages, shutdown interruption, duplicate command replay after restart, native resume with retained file context, and confirmed close. A later project Prompt override is rejected by readback, its source bytes remain unchanged, and source-change verification rejects reuse of the old snapshot.

The [recorded runtime result](probes/2026-09-18-opencode-configuration.json) covers a local protocol fixture. A separate [desktop session fixture](desktop-sessions.md) covers production factory/IPC/UI wiring, explicit version probing, renderer reattachment, and app quit/restart/resume. Neither result verifies an external model provider or passes V2/B7. Complete effective-policy reporting, other platforms, other API protocols, external MCP services/OAuth, broader plugin compatibility, and the intended external endpoint/key route remain required work. The separate [HTTP MCP fixture](http-mcp-acceptance.md) adds local authentication, tool/error and recovery evidence. [Runtime MCP observations](opencode-mcp-status.md) now record selected-service status at attachment and expose it in bilingual reports. See [selected ESM plugin activation](opencode-plugin-activation.md) for its production checks and separate evidence.

## Runtime event boundaries

Each turn converts assistant/reasoning text, tool updates, and permission choices into shared runtime payloads. Native tool and choice IDs stay inside the adapter; application IDs are generated per turn. Secret filtering spans text chunks independently for each channel. Text events are limited to 32,768 characters; tool content is capped at 65,536 characters with an explicit truncation flag. Native non-text message content, terminal content, and other ACP notifications are not presented by this adapter revision. Persistence callback failures close the attachment before another permission can be granted.

ACP usage is recorded with `scope: session` because its token counts are cumulative. Unknown cost remains null, and the native stop reason is retained. A cancel notification alone is not a completed cancellation; the prompt response supplies the terminal result. Resume verifies the original snapshot, reuses its mutable native state, and calls the advertised resume/load method for the original native session ID. If native restoration is unsupported or fails, the adapter fails instead of creating a new conversation.
