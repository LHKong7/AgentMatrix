# OpenCode configuration adapter

The current adapter targets **OpenCode 1.18.16**, with adapter contract `opencode-acp` version `1`. It generates run inputs and prepares a main-process launch. It is exercised against the installed CLI, but production engine discovery, effective-configuration gating, session coordination, and desktop session controls are not connected yet.

## Native mappings

| Shared configuration         | OpenCode mapping                                                                                                                                           | Current boundary                                                                                                                                                                      |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Connection and model         | Namespaced provider plus a `selected` model alias whose native `id` is the requested API model ID                                                          | Main and small-model routing use the selected connection. Provider acceptance remains specific to the endpoint/model/auth route                                                       |
| API protocol                 | Chat Completions → `@ai-sdk/openai-compatible`; Responses → `@ai-sdk/openai`; Anthropic Messages → `@ai-sdk/anthropic`; Gemini → `@ai-sdk/google`          | Only the Chat Completions route has a local wire-level fixture test. Other mappings are planned and unit-tested, not provider-verified                                                |
| Authentication               | Chat Completions supports none, bearer, or a selected API-key header. Responses supports bearer; Anthropic and Gemini support their native API-key headers | Engine login, cloud identity, and unverified combinations fail explicitly. No synthetic fallback credential is inserted                                                               |
| Sampling                     | Requested temperature and top-P map to the selected native agent                                                                                           | Unset fields stay unset. Temperature also enables the native custom-model capability flag. Model compatibility still needs verification. Reasoning settings currently fail explicitly |
| Replacement Prompt           | `agent.<name>.prompt` references a copied Prompt file                                                                                                      | Replaces the native provider/base role prompt; engine environment, project instructions, and other native system additions still apply                                                |
| Append / project-rule Prompt | Explicit copied paths in `instructions`                                                                                                                    | Preserves native instruction discovery. No project `AGENTS.md` file is rewritten                                                                                                      |
| Directory Skill              | Frontmatter name determines `skills/<name>/`; complete captured files are copied; `skills.paths` points at the run directory                               | Required name/description, portable native names, and duplicate selected names are checked. Native or remote Skill collisions still require effective readback                        |
| Plain Markdown Skill         | A generated native wrapper adds a stable name and description; the original text is retained separately under `sources/skills/`                            | Library contents are not changed. `opencode-mappings.json` records wrapper provenance and native paths                                                                                |
| stdio MCP                    | `type: local`, argv array, independent cwd, environment, enabled flag, and timeout                                                                         | Actual startup, secret environment, permission, and tool round trip pass the local fixture                                                                                            |
| Remote MCP                   | `type: remote`, URL, headers, bearer reference, timeout, and engine-owned OAuth scopes                                                                     | HTTP/OAuth server acceptance is unverified. A forced legacy-SSE selection fails because this config route does not force that transport                                               |
| Approval intent              | Selected agent permission is `ask`, `deny`, or `allow`                                                                                                     | Project/managed config and native agent behavior must still be inspected before claiming the effective policy                                                                         |
| Native plugins               | Explicitly rejected by this adapter revision                                                                                                               | Binding metadata does not install or activate a plugin. Normal CLI loading can still load plugins from its own existing native configuration                                          |

The provider SDK selection follows the [official custom-provider documentation](https://opencode.ai/docs/providers/#custom-provider). Prompt layering and sampling were checked against the [versioned request preparation code](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/opencode/src/session/llm/request.ts). MCP fields follow the [versioned native schema](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/core/src/v1/config/mcp.ts). Skill names and descriptions follow the [official Skill format](https://opencode.ai/docs/skills/); YAML parsing uses the [document API](https://eemeli.org/yaml/#documents) with bounded frontmatter, duplicate-key checks, no alias expansion, and no custom-tag execution.

## Files, precedence, and state

`OPENCODE_CONFIG` selects the captured `opencode.json`. Generated files include the schema field to avoid a native schema-insertion write. The adapter does not point `OPENCODE_CONFIG_DIR` at immutable inputs: OpenCode's [configuration loader](https://github.com/anomalyco/opencode/blob/v1.18.16/packages/opencode/src/config/config.ts) can write dependency and ignore files into resource directories. Skills use explicit paths instead.

Native configuration remains mergeable. Global configuration, project configuration, automatic resources, and managed settings retain their own precedence; see [OpenCode configuration locations](https://opencode.ai/docs/config/#locations). Project or managed settings can override captured intent. File generation must never be shown as proof that a requested value was applied. The production coordinator still needs to compare native readback before exposing a session as ready.

The source inspector records hashes or absence for known config/rule candidates, traversing the canonical cwd to the nearest Git root. It records configured global/home locations and supplied managed-file candidates without copying their contents. Coverage stays **partial**: arbitrary plugin/Skill trees, remote sources, included files, legacy formats, and live policy are not fully enumerated. Callers must supply the platform's managed locations; omission is not proof that managed policy is absent.

Native data, cache, state, and temporary files use separate directories under the run's mutable `state` tree. Global config remains at the selected native config home. This is native storage routing, not a filesystem sandbox or a guarantee that third-party plugins write only there. Existing native authentication stores are not imported, so engine-login routes are not yet supported.

## Credentials and interpolation

Snapshots contain secret references and generated environment aliases. `prepareRunLaunch` verifies the snapshot, resolves only its explicit references, deduplicates each reference for that launch, and builds a minimal process environment. Raw values and their injected encodings are kept in memory for diagnostic redaction; they are not written into generated config or the snapshot manifest.

OpenCode substitutes environment macros before parsing JSON. Secret aliases therefore use `json-string` encoding, which escapes quotes, backslashes, and opening braces. Ordinary user strings are also protected from accidental native macro expansion. Only adapter-created file/environment expressions expand. The installed-CLI probe verifies an API key containing both quotes and a file-like macro reaches the local endpoint unchanged. This does not imply that arbitrary user-authored prompt text or native plugin output can be classified as secret automatically.

## Reproducible native probe

```sh
AGENT_MATRIX_TEST_OPENCODE=/absolute/path/to/opencode \
AGENT_MATRIX_OPENCODE_REPORT=/absolute/path/to/report.json \
npm run probe:opencode
```

The opt-in probe uses temporary home/config/state directories, a local HTTP protocol fixture, synthetic credentials, and `--pure`. It verifies the installed version, native config readback, provider routing, replacement and appended Prompt content in requests, Markdown and directory Skill discovery, actual directory Skill invocation, streamed response, permission replies, file-read and stdio-MCP tool round trips, MCP cwd/argv/environment, and input integrity after exit. Source/capture deletion demonstrates the session uses its own Skill copies. A later project Prompt override is read back, its source bytes remain unchanged, and source-change verification rejects reuse of the old snapshot.

The [recorded macOS result](probes/2026-09-18-opencode-configuration.json) covers a protocol fixture, not an external model provider or the desktop UI. It does not pass V2 or B7. Native cancellation/resume, effective-policy enforcement, other platforms, other API protocols, remote MCP/OAuth, plugin activation, and the intended external endpoint/key route remain required work.
