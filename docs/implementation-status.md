The active application reads/writes schema v2 through a single store. Existing v1 files migrate with exact-byte backups; browser preview retains its old v1 key. All nine configuration collections have compatible English/Chinese editors. Native CLI installations used for probes are not automatically registered as user profiles. Saving an installation path does not execute a CLI. The explicit desktop Check installation action probes OpenCode, Pi, or DSH; only their pinned supported versions enable ACP or Pi RPC launch.

Latest verification: 356 unit tests, two opt-in installed-CLI ACP initialization/cleanup checks, an installed OpenCode runtime probe against a local protocol fixture (including two cancellation paths, native resume with retained history, permission persistence failure, override rejection, coordinator command replay, journal/event parity, and restart/resume), ESLint, TypeScript, production build, and changed-file formatting passed. Real Electron verification covers exact-byte v1 migration, all three engine drafts, Pi trust/context and DSH instruction placement, shared connections/models, prompt and Skill revisions, directory capture/reimport, pinned/latest bindings, bundles, bilingual diagnostics, deletion cleanup, restart, and OS-encrypted credential creation/replacement/deletion. The native folder chooser is substituted in the smoke test; the actual import IPC, capture service, filesystem, and editors run unchanged. The configuration smoke uses synthetic credentials without executing agents. A separate [desktop session smoke](desktop-sessions.md) runs installed OpenCode, Pi, and DSH against local synthetic providers, verifying explicit installation probing, profile-to-session capture, streamed/tool output, OpenCode permission replies and both cancellation paths, Pi streaming cancellation, renderer reload without resubmission, old/new shared-Prompt snapshots, app quit/restart, native resume, confirmed close, bilingual controls, escaped untrusted text, and journal key redaction. These fixtures do not call an external model provider.

The opt-in installed Pi probe additionally passes the [local RPC lifecycle fixture](pi-rpc.md), including Unicode streaming, tool context after native restoration, provider errors after acceptance, extension command handling without a model run, and unchanged unrelated trust decisions. The [saved-profile configuration fixture](pi-configuration.md) also passes actual directory Skill/reference reads, old/new prompt inputs, literal/secret headers, native state verification, and execution/trust/context choices. The [Pi runtime and desktop fixtures](pi-runtime.md) now pass normalized text/tool output, split-key redaction, durable command replay, streaming cancellation, post-acceptance provider errors, immutable snapshot reuse, renderer reload, and native restoration. English/Chinese desktop controls enable Pi 0.85.1 profiles with compatible execution policies. Universal tool approval remains unavailable.

The installed DSH ACP lifecycle also passes separately through its pi-ai gateway component and native DeepSeek component, both against local Chat Completions fixtures. [Results](dsh-acp.md) establish the selected route's feasibility and its committed-output, usage, and replay limits. All three engines now have early local lifecycle evidence; this does not replace external provider or complete desktop acceptance.
