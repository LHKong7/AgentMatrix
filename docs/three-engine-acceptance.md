# Initial three-engine acceptance checklist

Reviewed: **2026-09-19**. This is the X2 record for the twelve requirements in [research section 9.2](cli-agent-research.md#92-acceptance-checklist-for-every-adapter). ## Reading the record

**Local pass** means the stated behavior passes on the recorded macOS arm64 host with controlled inputs. **Partial** means an explicit part of the requirement still lacks sufficient evidence. **Unsupported, guarded** means a requested feature is rejected and remains visibly unavailable; it is not a working integration. No local provider result proves compatibility with a user's external service.

The [audit run record](probes/2026-09-19-three-engine-acceptance.json) identifies the application revision, commands, unit results and fresh desktop reports. Reports now include the selected executable, service, protocol and model, in addition to engine version, platform and time. Older feature reports retain their original scope and timestamps; their filenames are not proof of when a check ran. Tests were inspected for relevant assertions, not treated as sufficient merely because their names matched a requirement.

## Evidence A: lifecycle and desktop behavior

Initial audit reports: [OpenCode](probes/2026-09-19-acceptance-opencode-desktop.json), [Pi](probes/2026-09-19-acceptance-pi-desktop.json), [DSH Pi-AI](probes/2026-09-19-acceptance-dsh-desktop.json). The common source is [session-smoke.mjs](../scripts/session-smoke.mjs). Its assertions check native version probing; profile-to-session launch; typed/selected working directories; actual file tools; plugin hooks; bilingual reports; immutable revisions; reload; cancellation; quit/restart; main-process `SIGKILL`; removal of owned groups; original native ID/snapshot on explicit resume; history/export; close; and reference-aware cleanup.

The subsequent [native DeepSeek](probes/2026-09-19-dsh-desktop-deepseek-native.json) and [Pi-AI](probes/2026-09-19-dsh-desktop-pi-ai.json) runs execute the full fixture separately. The [DSH runtime record](dsh-runtime.md#full-desktop-checks-for-both-provider-routes) describes route identity and native reasoning assertions. Native-route English/Chinese report screenshots were visually inspected; this is additional evidence beyond the initial audit.

The initial audit's language checks exercise controls and text; they are not a new screenshot-based visual inspection. MCP report checks do not independently execute an MCP tool. Pi reports unsupported permission operations as strings rather than passing booleans. DSH reports committed messages rather than claiming incremental UI streaming.

[DSH runtime evidence](dsh-runtime.md) includes both Pi-AI and native DeepSeek cases from [dsh-runtime-installed.probe.ts](../tests/dsh-runtime-installed.probe.ts). [OpenCode configuration](opencode-configuration.md) and [DSH configuration](dsh-configuration.md) have actual native denied-tool checks. [Pi RPC](pi-rpc.md) covers its different interaction contract. These native-runtime/denial checks remain distinct from the full Electron reruns; the later desktop tests add native-route recovery and cleanup evidence.

## Evidence B: shared assets and immutable inputs

The [combined shared-asset record](probes/2026-09-19-shared-assets-desktop.json) verifies eighteen turns across six conversations, one shared Prompt and directory Skill, simultaneous active-turn edits, native reference-file reads, old/new versions after restart and independence from changed/deleted import sources. [The fixture](../scripts/shared-assets-smoke.mjs) correlates tool outputs with each turn's call IDs rather than accepting an old transcript marker.

[Run-input tests](../tests/run-input-store.test.ts) assert distinct mutable native-state directories, concurrent captures, retained old bytes and unchanged manifests. [Factory tests](../tests/session-desktop-factory.test.ts) assert capture without credential resolution, stable retry identity and rejection before source inspection for invalid directories. [Resolution](../tests/engine-resolution.test.ts), [configuration reports](../tests/configuration-report.test.ts) and [impact previews](../tests/library-impact.test.ts) cover direct/bundle precedence, fixed/latest bindings and saved-versus-captured versions.

[Responses acceptance](responses-provider-acceptance.md) and its [three-case record](probes/2026-09-19-responses-provider-acceptance.json) verify selected Bearer/header credentials, proxy paths, split argument streams, real file results, cancellation, native resume and HTTP failures. ## Evidence D: MCP

The native [HTTP MCP fixture](../tests/mcp-http-installed.probe.ts) checks request-header separation, tool results/errors and native restoration for [OpenCode](probes/2026-09-19-http-mcp.opencode.json), [DSH Pi-AI](probes/2026-09-19-http-mcp.dsh-pi-ai.json) and [DSH native DeepSeek](probes/2026-09-19-http-mcp.dsh-deepseek-native.json). [HTTP acceptance boundaries](http-mcp-acceptance.md) distinguish Streamable HTTP SSE encoding from legacy SSE and initialization from continuous connectivity.

[OpenCode](../tests/opencode-installed.probe.ts) and [DSH](../tests/dsh-configuration-installed.probe.ts) configuration probes exercise stdio MCP with argument arrays and selected environments. [Process tests](../tests/managed-process.test.ts) pass shell-looking arguments literally and exclude ambient loader options/keys. [Capability guards](../tests/engine-capabilities.test.ts) explicitly reject Pi MCP/universal approvals and DSH OAuth/forced legacy SSE while retaining drafts. No test in this record establishes OpenCode OAuth login or refresh.

[Selected native import](native-configuration-import.md), [Pi import](pi-native-configuration-import.md) and [DSH import](dsh-native-configuration-import.md) preserve selected source bytes, known credential references and unknown-field diagnostics without writing back to the original files. [Skill capture](skill-capture.md) preserves directory contents and flags. Plugin checks cover selected [OpenCode](opencode-plugin-activation.md), [Pi](pi-plugin-activation.md) and [DSH](dsh-plugin-activation.md) contracts, plus partial [dependency observations](plugin-dependency-sources.md).

[Configuration reporting](configuration-report.md), [instruction sources](opencode-instruction-sources.md) and [override candidates](opencode-override-sources.md) preserve observed scope and historical identity. A matching literal declaration is a candidate, not proof of the winning source. Missing readback remains unknown; generated configuration alone is not effective-value evidence.

## Evidence F: shared contracts and data boundaries

The fresh unit run passes **923 tests in 61 files**, with at most two workers. [Migration](../tests/engine-migration.test.ts), [workspace publication](../tests/engine-workspace-store.test.ts), [capabilities](../tests/engine-capabilities.test.ts), [coordinator](../tests/session-coordinator.test.ts), [ACP turns](../tests/acp-turn.test.ts), [Pi turns](../tests/pi-turn.test.ts), [IPC](../tests/session-ipc.test.ts) and [journal](../tests/session-journal.test.ts) tests establish the shared guard and persistence behavior used above. Assertions cover preserved references, exact interaction correlation, late answers, journal-first actions, cleanup failures and renderer ownership.

[Credential-history acceptance](credential-redaction-history.md) covers all three engines on the Pi-AI DSH route with real OS encryption, rotation, restart, old-key echoes, journal/export scans and retained masking-copy cleanup. [Its record](probes/2026-09-19-credential-redaction-history-desktop.json) is earlier evidence, not a new full X3 audit. [Process/crash tests](process-crash-recovery.md) and the fresh desktop cases cover owned group cleanup; they do not establish an OS sandbox or prevent native code from opening unrelated user files.

The earlier [configuration editor record](probes/2026-09-19-plugin-options-editor.json) is emitted after [the smoke script](../scripts/smoke.mjs) checks exact-byte migration backup, OS decryption, credential replacement/deletion and bilingual editing in addition to the plugin fields listed in that report. New desktop checks in this audit do not repeat every configuration editor action. Native transcripts/caches may retain raw model content, including echoed keys; application masking does not rewrite those files.

## Remaining work and gate decisions

The X2 checklist artifact now exists. Its partial rows remain partial, and B7/C4/D4 are not promoted by collecting the reports. B0 requires its own foundation acceptance decision; an external provider is not a B0 prerequisite.

| Next work                             | Required evidence / decision                                                                                                                                                                                                                   |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Intended external provider acceptance | For each initial engine, record the selected endpoint, protocol, model and local credential reference; exercise a real streamed turn and tool result. This needs the user's intended service details, still pending.                           |
| X3 audit                              | Enumerate application log, stderr, event, interaction, journal, preview, export and input-storage paths; verify selected credentials and run boundaries with adversarial fixtures. Keep native plaintext-state limits explicit.                |
| Native precedence and Skill behavior  | Identify the exact source combinations and lazy-loading/collision cases still needed for the supported configurations. Supply native evidence or preserve an explicit unknown/unsupported boundary; never infer a winner from candidate files. |
| OpenCode OAuth                        | Validate login/refresh/tool use if claimed for delivery, or keep it explicitly unverified without inheriting non-OAuth evidence. Pi core and DSH unsupported OAuth do not need invented implementations.                                       |

Unknown native readback is explicitly permitted by B6 when reported honestly. A general plugin marketplace, arbitrary plugin installation, automatic upgrades, full Pi MCP-extension support, other six engines and release signing remain outside this milestone. Complete dynamic dependency closure is not silently added as a new release requirement. Other operating systems need their own checks before being advertised; these macOS results cannot pass Linux or Windows acceptance.

## Reproduction

Run `npm run lint`, `npm run build`, then `npx vitest run --maxWorkers=2`. Run each [desktop session command](desktop-sessions.md#reproducible-verification) sequentially against that build, selecting one engine and an explicit executable. Set `AGENT_MATRIX_SESSION_REPORT` to retain its JSON result. Do not rebuild while a native/Electron suite is active. Auxiliary provider, shared-asset, import and credential fixtures keep their documented commands and scopes; this checklist does not imply every historical fixture ran again.
